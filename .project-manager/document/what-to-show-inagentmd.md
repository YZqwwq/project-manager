# 项目规则入口应包含什么

## 定位

project-manager 首次接入项目时，建立或整合宿主 Agent 支持的项目规则入口。入口保持轻量，让每次任务都能看到责任划分、skills 导航、文档导航及管理行为的规范入口；详细内容按需读取。

## 核心约定

- **按领域承担责任**：根据当前任务目标、操作对象和涉及范围选择规范。处理前端时遵守前端规范，处理后端时遵守后端规范，同时处理时分别应用，规则不跨范围扩散。
- **动态挂载与退出**：相关工作开始前读取规范；任务明确退出某领域后，停止应用该领域规则。临时提问不自动取消仍在进行的任务。“卸载”指停止适用，不承诺从上下文物理删除。
- **按任务选择自动化**：需要埋点等能力时，先查找已登记的 skills，核对适用环境后读取并执行。登记不等于执行授权，使用过一次也不自动成为长期规范。
- **管理动作有对应规范**：添加或调整 skill、编写项目管理文档、维护规则入口时，先读取 project-manager 对应细分规范。
- **区分使用与变更权限**：在任务授权内应用已有规范和能力；改变长期规范、分类或适用范围时，遵循管理规范与用户已有授权，不重复索取已明确的授权。

## 入口常驻内容

1. 任务责任判断、规范加载和退出规则。
2. 仅规范类 skills 的摘要表：名称、职责摘要和入口。按语义匹配相关规范，不要求遍历 skill 目录。按需工具不列入表中，只提供工具目录位置和按需检索要求。
3. 项目目标、现状、阶段计划的位置与用途。计划是背景，不是自动执行指令。
4. 新 skill 的存放与登记入口，以及项目文档和规则入口的维护规范入口。
5. 权限边界：读取或调用 skill 不扩大用户授权，不自行改变项目长期约定。

入口不展开具体业务规范、自动化步骤、文档模板或完整项目内容。

## 本次预览约定

`agent.md` 是供审阅的入口示例，假设存在 `projectManager/skill/` 和 `projectManager/文档/`。其中 skills 名称及细分路径用于演示，尚未创建或验证。正式接入时替换为真实登记内容，并使用宿主支持的文件名（例如 Codex 的 `AGENTS.md`）。

## 第一层检索约定

- `AGENTS.md` 直接登记规范摘要，具体规范在任务匹配后读取。管理 skill 即使只在特定动作中适用，也按其规范职责归类。
- `.project-manager/skill/tools.md` 单独登记按需工具，包含名称、用途摘要、必要适用条件和入口；只有需要自动化能力时才读取或检索。
- 添加或调整 skill 时整理摘要并更新对应登记；分类改变时同步移除旧条目，不维护两份相同索引。
- 规范及用途摘要采用自然语言，不穷举触发词。工具一次执行结束后停止适用，目录登记仍可复用。
- 实际管理目录为 `.project-manager/document/` 和 `.project-manager/skill/`；上面的预览约定仅记录早期讨论。
